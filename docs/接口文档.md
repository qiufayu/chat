> 本文档基于 `ChatSystem`（Spring Boot + Netty + RabbitMQ 即时通讯后端）源码自动梳理，覆盖全部 HTTP 接口与 WebSocket 接口，并重点说明各接口的鉴权要求。
> 生成时间：2026-11-12
> 适用代码范围：`ChatSystem/chat-user`、`chat-group`、`chat-message`、`chat-gateway`、`chat-connection`

## 一、服务与访问地址概览

| 服务 | 角色 | 直连端口 | 网关路由前缀 | 说明 |
| --- | --- | --- | --- | --- |
| chat-gateway | API 网关 / 鉴权 | 8080 | 统一入口 | 全局 JWT 鉴权、服务发现与路由 |
| chat-user | 用户 / 认证 / 好友 | 8081 | `/user/**`、`/friend/**` | 登录注册、令牌刷新、好友 |
| chat-group | 群组 / 成员 | 8082 | `/group/**` | 建群、入群 |
| chat-message | 消息 / 会话 / 同步 / Outbox | 8083 | `/sync/**`（当前配置） | 消息落库、设备同步游标、ACK |
| chat-connection | Netty WebSocket 连接 | 9000 | `/ws/**`（ws 转发到 9000） | 实时收发、心跳、在线推送 |

**重要路由说明**：当前网关 `application.yaml` 仅显式路由了 `/user/**`、`/friend/**`、`/group/**`、`/sync/**` 与 `/ws/**`。
消息服务中定义在 `/msg`、`/conversation`、`/outbox` 下的接口**暂未配置网关路由**，如需通过网关访问需补充路由；现阶段可直接访问消息服务端口 `:8083`。下文每个接口都已标注其所在服务与基础路径。

## 二、鉴权说明（调用方必读）

### 2.1 整体鉴权模型

1. 客户端统一请求**网关 `:8080`**（或经网关的 WebSocket 入口）。
2. 网关全局过滤器 `AuthGlobalFilter` 拦截所有请求（`OPTIONS` 预检请求直接放行）。
3. 对于**非白名单**路径，网关从请求头读取 `authorization`（JWT）与 `device-id`：
   - 解析 JWT 得到 `userId`；解析失败/过期/为空 → 返回 **HTTP 401**。
   - 校验通过后，网关向转发给下游的请求**注入** `user-info`（值为 `userId` 字符串）与 `device-id` 头。
4. 下游服务通过 `UserInfoInterceptor` 读取 `user-info` 头，写入线程级 `UserContext`，供业务获取当前登录用户。
5. WebSocket：`/ws` 握手是 HTTP GET 请求，同样经过网关过滤器鉴权；握手成功后连接服务从握手请求头读取 `user-info` 与 `device-id`，完成 `channel ⇄ (userId + deviceId)` 绑定。

### 2.2 请求头说明

| 头名称 | 是否必填 | 取值格式 | 传递方式 | 说明 |
| --- | --- | --- | --- | --- |
| `authorization` | **除白名单接口外必填** | 登录/刷新后获得的 **accessToken 原始 JWT 字符串**（**不带** `Bearer ` 前缀） | HTTP 请求头（及 WS 握手头） | 网关据此解析 `userId` 并鉴权；缺失或非法 → 401 |
| `device-id` | **WebSocket 握手必填**；HTTP 请求强烈建议携带 | 客户端首次启动生成的设备唯一标识，字符串，长度 **≤ 64** | HTTP 请求头（及 WS 握手头） | 用于多设备绑定与设备同步游标；网关会读取并向下游透传 |
| `user-info` | **由网关注入，调用方请勿自行设置** | `userId` 字符串（如 `"1001"`） | 内部头（网关→下游） | 下游服务据此识别当前用户身份 |

> 实现备注：网关过滤器在鉴权成功时会同时读取 `authorization` 与 `device-id` 两个头并向下游透传，因此**建议所有已鉴权请求都成对携带 `authorization` 与 `device-id`**；WebSocket 场景下 `device-id` 缺失将直接导致连接被拒绝。

### 2.3 白名单（免鉴权）接口

以下接口**不需要** `authorization` 头，调用方可匿名访问（网关 `chat.auth.excludePaths` 配置）：

- `POST /user/login`
- `POST /user/register`
- `POST /user/refresh`

### 2.4 Token 说明与刷新流程

- JWT 算法：**RS256**（密钥库 `hmall.jks`，alias `hmall`）。
- JWT payload 中 `user` 字段即为 `userId`（Long）。
- `accessToken` 有效期：**30 分钟**；`refreshToken` 有效期：**30 天**（见各服务 `chat.jwt` 配置）。
- **刷新流程**：客户端收到 401（或 accessToken 临近过期）时，调用 `POST /user/refresh` 并传入 `refreshToken`，服务端返回新的 `accessToken`（必要时返回新的 `refreshToken`）。

### 2.5 鉴权失败表现

- HTTP 接口：返回 **HTTP 401**（响应体由异常处理决定，网关阶段直接置状态码并结束响应）。
- WebSocket：握手请求若缺少 `user-info` 或 `device-id`，连接服务会**直接关闭连接**。

## 三、HTTP 接口清单

### 3.1 用户服务（chat-user，基础路径 `/user`、`/friend`）

#### 3.1.1 `GET /user`
- **功能**：服务连通性探测（网关探活）。
- **鉴权**：需要（匹配 `/user/**`，非白名单）。
- **请求参数**：无。
- **响应**：无内容（204）。

#### 3.1.2 `POST /user/login` ⭐ 免鉴权（白名单）
- **功能**：用户登录，获取访问令牌。
- **鉴权**：**不需要**。
- **请求体（JSON）**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | account | String | 是 | 登录账号 |
  | password | String | 是 | 密码 |
- **响应（UserLoginVO）**：
  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | accessToken | String | 访问令牌（JWT，后续请求放入 `authorization` 头） |
  | refreshToken | String | 刷新令牌（用于 `/user/refresh`） |

#### 3.1.3 `POST /user/register` ⭐ 免鉴权（白名单）
- **功能**：用户注册，注册成功直接返回令牌。
- **鉴权**：**不需要**。
- **请求体（JSON）**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | phone | String | 是 | 手机号 |
  | password | String | 是 | 密码 |
  | nickname | String | 是 | 昵称 |
- **响应（UserRegisterVO）**：
  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | account | String | 注册后生成的账号 |
  | accessToken | String | 访问令牌 |
  | refreshToken | String | 刷新令牌 |

#### 3.1.4 `GET /user/info`
- **功能**：获取当前登录用户的基本信息（当前用户由网关注入的 `user-info` 头确定）。
- **鉴权**：需要。
- **请求参数**：无。
- **响应（UserInfoVo）**：
  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | account | String | 账号 |
  | nickname | String | 昵称 |
  | avatar | String | 头像地址 |

#### 3.1.5 `POST /user/refresh` ⭐ 免鉴权（白名单）
- **功能**：使用 refreshToken 刷新 accessToken（建议在收到 401 时调用）。
- **鉴权**：**不需要**。
- **请求体（JSON）**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | refreshToken | String | 是 | 刷新令牌（非空校验） |
- **响应（TokenResponseVO）**：
  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | accessToken | String | 新的访问令牌 |
  | refreshToken | String | 刷新后新的刷新令牌（若未轮换则可不返回） |

#### 3.1.6 好友申请与管理（2026-11-24更新）

好友申请需要接收方同意，有效期7天。所有接口需要登录，当前身份由网关确定；`senderId` 不能冒充其他用户。

| 方法与路径 | 参数/请求体 | 响应 |
| --- | --- | --- |
| `GET /friend/search` | `account` 或 `userId` 二选一 | 公开账号资料 |
| `POST /friend/apply` | `{"account":"对方账号","message":"申请说明"}`；可用 `friendId` 替代账号 | 申请对象，初始 `PENDING` |
| `GET /friend/requests` | `direction=incoming/outgoing`，可选 `beforeId`，`limit=1..100`（默认50） | 本人收到/发出的申请 |
| `POST /friend/requests/{requestId}/accept` | 申请ID，仅接收人可调用 | 申请最终状态 |
| `POST /friend/requests/{requestId}/reject` | 申请ID，仅接收人可调用 | 申请最终状态 |
| `GET /friend/list` | `afterId=0`，`limit=1..100`（默认50） | 本人好友列表 |
| `POST /friend/verify` | `{"toId":2}`；兼容可选 `senderId`，须与登录用户相同 | `boolean`，是否允许单聊 |
| `DELETE /friend/{friendId}` | 对方用户ID | 204，双向解除，保留历史 |

申请对象：`id`、`applicantId`、`receiverId`、双方账号/昵称、`message`、`status`、`createdAt`、`expiresAt`、`handledAt`。终态包括 `ACCEPTED`、`REJECTED`、`EXPIRED`、`CANCELLED`，重复处理只返回最终状态，不重新建立关系。申请按ID倒序分页，好友按对方ID升序分页。

同向待处理申请重复发送返回同一记录；双方交叉申请不会自动同意。同意后事务内建立双向关系；删除后双方禁止新的单聊发送，再次成为好友必须重新申请和同意。校验以数据库为准，缓存残留不能绕过权限检查。参数/业务错误返回公共格式 `{"code":400,"message":"..."}` 与对应 HTTP 状态码。

部署前须执行新增申请表的增量脚本；完整说明、账号状态兼容事项和验证命令见 [好友链路与接口](好友链路.md)。

- **功能**：提交「设备已连续收到并保存消息」的确认，推进设备同步游标（幂等，不会倒退）。
- **鉴权**：需要。
- **请求参数（Query）**：`userId`(Long, 是)。
- **请求体（JSON，DeliveryAckDTO）**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | deviceId | String | 是 | 设备 ID |
  | conversationId | Long | 是 | 会话 ID |
  | ackSeq | Long | 是 | 已确认收到的最大连续序号 |
- **响应**：`boolean`（是否更新成功）。

#### 3.3.15 `POST /sync/read/ack`
- **功能**：提交「用户已读」确认，推进用户阅读位置（幂等，只向前）。
- **鉴权**：需要。
- **请求参数（Query）**：`userId`(Long, 是)。
- **请求体（JSON，ReadAckDTO）**：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | deviceId | String | 是 | 设备 ID |
  | conversationId | Long | 是 | 会话 ID |
  | readSeq | Long | 是 | 已读到的序号 |
- **响应**：`boolean`。

#### 3.3.16 `GET /sync/interval/sync`
- **功能**：客户端主动区间同步（不走 WebSocket，每次最多拉取 100 条，用于断线后补拉指定区间）。
- **鉴权**：需要。
- **请求参数（Query）**：
  | 参数 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | deviceId | String | 是 | 设备 ID |
  | conversationId | Long | 是 | 会话 ID |
  | start | Long | 是 | 区间起始序号 |
  | end | Long | 是 | 区间结束序号 |
- **响应（SyncBatchVO）**：结构同 3.3.13（消息批次）。

## 四、WebSocket 接口（单独说明）

### 4.1 连接入口与鉴权

- **连接地址**：`ws://<host>:9000/ws`（经网关则为 `ws://<host>:8080/ws`，网关将 `/ws/**` 转发到 `:9000`）。
- **传输格式**：文本帧（`TextWebSocketFrame`），内容为 **JSON 字符串**。
- **握手鉴权（必填）**：
  - `authorization` 头：登录获得的 accessToken（JWT，不带 `Bearer ` 前缀）。
  - `device-id` 头：设备唯一标识（长度 ≤ 64）。
  - 网关校验 JWT 后注入 `user-info` 头；连接服务在握手完成时读取 `user-info` 与 `device-id`，**任一为空则直接关闭连接**。
- **多设备**：同一用户可绑定多设备，每设备仅保留一个活动通道（`channel ⇄ userId+deviceId`）。
- **心跳**：客户端发送文本 `"PING"`，服务端回 `"PONG"`；读空闲 60s 探测、120s 无心跳断开。

### 4.2 服务端→客户端：连接就绪与同步摘要

**`CONNECTION_READY`**（握手成功后立即下发）
```json
{ "type": "CONNECTION_READY", "deviceId": "device-a", "serverTime": 1760000000000 }
```

**`SYNC_SUMMARY`**（连接成功后异步下发，各会话待同步摘要）
```json
{
  "type": "SYNC_SUMMARY",
  "conversations": [
    { "conversationId": 1001, "lastSyncedSeq": 25, "lastSeq": 28, "pendingCount": 3 }
  ]
}
```

### 4.3 客户端→服务端：请求帧

**`CHAT`**（发送单聊/群聊消息；`senderId`、`deviceId`、`seq` 由连接自动填充，`clientMessageId` 必须保持稳定以支持幂等重试）
```json
{
  "type": "CHAT",
  "toId": 2002,
  "clientMessageId": "client-msg-001",
  "payload": { "contentType": "TEXT", "content": "你好" }
}
```
- `payload.contentType`：`TEXT` / `FILE`（图片或文件时用 `attachmentId`）。
- 请求参数（帧内字段）：
  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | type | String | 是 | 固定 `CHAT` |
  | toId | Long | 是 | 接收者用户 ID |
  | clientMessageId | String | 是 | 客户端消息 ID（不可为空，幂等键） |
  | payload.contentType | String | 是 | 内容类型 |
  | payload.content | String | 文本时必填 | 文本正文 |
  | payload.attachmentId | Long | 文件/图片时 | 附件 ID |

**`SYNC_REQUEST`**（请求同步某会话消息）
```json
{ "type": "SYNC_REQUEST", "conversationId": 1001, "afterSeq": 25, "limit": 50, "requestId": "sync-001" }
```
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | String | 是 | 固定 `SYNC_REQUEST` |
| conversationId | Long | 是 | 会话 ID |
| afterSeq | Long | 否 | 起始序号（默认 0） |
| limit | Integer | 否 | 上限（默认 50） |
| requestId | String | 否 | 请求标识（回包带回） |

**`DELIVERY_ACK`**（设备已连续接收并保存消息，推进设备游标）
```json
{ "type": "DELIVERY_ACK", "conversationId": 1001, "ackSeq": 26 }
```
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | String | 是 | 固定 `DELIVERY_ACK` |
| conversationId | Long | 是 | 会话 ID |
| ackSeq | Long | 是 | 已确认最大连续序号（不可跳号） |

**`READ_ACK`**（用户已读确认，推进阅读位置）
```json
{ "type": "READ_ACK", "conversationId": 1001, "readSeq": 26 }
```
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | String | 是 | 固定 `READ_ACK` |
| conversationId | Long | 是 | 会话 ID |
| readSeq | Long | 是 | 已读序号 |

### 4.4 服务端→客户端：响应/推送帧

**`SAVED_ACK`**（消息已可靠保存；注意：**不代表**接收方已收到或已读）
```json
{
  "type": "SAVED_ACK", "status": "SAVED",
  "clientMessageId": "client-msg-001", "messageId": 501,
  "conversationId": 1001, "seq": 26, "serverTime": 1760000000000
}
```
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | 固定 `SAVED_ACK` |
| status | String | 固定 `SAVED` |
| clientMessageId | String | 回显客户端消息 ID |
| messageId | Long | 服务端消息 ID |
| conversationId | Long | 会话 ID |
| seq | Long | 分配的消息序号 |
| serverTime | Long | 服务端时间戳（毫秒） |

**`SEND_ERROR`**（发送/处理失败）
```json
{ "type": "SEND_ERROR", "clientMessageId": "client-msg-001", "message": "消息保存失败" }
```
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | 固定 `SEND_ERROR` |
| clientMessageId | String | 关联客户端消息 ID |
| message | String | 错误描述 |

**`MESSAGE`**（在线推送：接收方在线时由服务端下发新消息）
```json
{
  "type": "MESSAGE", "messageId": 501, "conversationId": 1001, "seq": 26,
  "sendId": 1001, "senderId": 1001, "toId": 2002, "messageType": 1,
  "payload": { "content": "你好" }
}
```
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | 固定 `MESSAGE` |
| messageId | Long | 消息 ID |
| conversationId | Long | 会话 ID |
| seq | Long | 消息序号 |
| sendId / senderId | Long | 发送者 ID |
| toId | Long | 接收者 ID |
| messageType | Integer | 消息类型（1 文本 / 2 图片 / 3 文件） |
| payload | Object | 消息体（文本含 `content`，文件/图片含 `attachmentId`） |

**`SYNC_BATCH`**（响应 `SYNC_REQUEST` 的同步批次）
```json
{
  "type": "SYNC_BATCH", "requestId": "sync-001", "conversationId": 1001,
  "nextSeq": 76, "hasMore": true,
  "messages": [
    { "messageId": 502, "conversationId": 1001, "seq": 26, "senderId": 1001,
      "messageType": 1, "textContent": "你好", "attachmentId": null,
      "isRecalled": 0, "isBlocked": 0, "createdAt": "2026-10-30T12:00:00" }
  ]
}
```
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | 固定 `SYNC_BATCH` |
| requestId | String | 回显同步请求 ID |
| conversationId | Long | 会话 ID |
| nextSeq | Long | 下一批起始序号 |
| hasMore | boolean | 是否还有更多 |
| messages | Array | 消息数组（结构同 `SyncMessageVO`） |

**`DELIVERY_ACK` / `READ_ACK`**（服务端对 ACK 的回显确认）
```json
{ "type": "DELIVERY_ACK", "conversationId": 1001, "ackSeq": 26 }
{ "type": "READ_ACK", "conversationId": 1001, "readSeq": 26 }
```

**`PONG`**（响应心跳）
```
PONG
```

### 4.5 WebSocket 鉴权小结（调用方要点）

1. 建立 WS 连接前，先通过 `POST /user/login` 获取 `accessToken`。
2. 发起 `ws://<host>:8080/ws` 握手时，请求头必须携带：
   - `authorization: <accessToken>`（原始 JWT，无 `Bearer ` 前缀）
   - `device-id: <设备唯一标识，≤64 字符>`
3. 握手通过后，服务端下发 `CONNECTION_READY`；随后方可发送 `CHAT` / `SYNC_REQUEST` / `DELIVERY_ACK` / `READ_ACK` 等业务帧。
4. `device-id` 必须在设备重装/重连时保持一致，否则设备同步游标无法连续推进。

## 五、错误码与状态码

| 状态码 / 表现 | 含义 | 触发场景 |
| --- | --- | --- |
| HTTP 401 | 未鉴权 / 令牌无效或过期 | `authorization` 缺失、JWT 解析失败或过期（白名单接口除外） |
| 400 | 参数错误 | 如聊天消息缺少 `toId`/`clientMessageId`、`messageType` 为空等（`BaseException`） |
| 403 | 业务拒绝 | 如对方不是好友或已被拉黑（`BaseException`） |
| 500 | 服务内部错误 | 消息保存失败等 |
| WS 连接被关闭 | 握手缺少 `user-info` 或 `device-id` | WebSocket 鉴权失败 |
| `SEND_ERROR` 帧 | 消息处理失败 | WS 发送链路异常，附带 `message` 描述 |

## 六、附录：关键约定速查

- **鉴权头**：`authorization`（JWT，无 `Bearer ` 前缀）+ `device-id`（≤64 字符）。
- **白名单（免鉴权）**：`POST /user/login`、`POST /user/register`、`POST /user/refresh`。
- **Token**：RS256，payload.user = userId；access 30 分钟、refresh 30 天；过期用 `/user/refresh` 轮换。
- **幂等键**：消息发送以 `senderId + clientMessageId` 保证幂等，客户端重试须复用同一 `clientMessageId`。
- **WS 端口**：直连 `:9000/ws`，经网关 `:8080/ws`。
- **网关当前未路由**：`/msg`、`/conversation`、`/outbox`（消息服务直连 `:8083` 或通过 Feign 内部调用）。
- **消息状态层次（不可混用）**：`SAVED_ACK`（已保存）→ `SENT`（已发布到 MQ）→ `DELIVERY_ACK`（设备已收）→ `READ_ACK`（用户已读）。
